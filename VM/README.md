# VM guest → host mouse control

Run host_receiver.py **on the host computer** with the host user's permission. Open its pairing URL **inside the virtual machine**. The guest browser sends authenticated mouse commands to the host receiver over their shared virtual network. The receiver uses the host's normal Windows, Ubuntu, or macOS mouse API. This is an explicit network connection; VM isolation stays in place.

## Network setup

Use a host-only virtual network when possible. Configure it in your VM application's network settings so the host and guest each have an IPv4 address on that network. Keep your usual internet adapter if needed. Record both addresses. This program does not change VM settings, install guest integration tools, or configure forwarding. Network setup differs between VM applications. A bridged connection on a trusted private network can also work.

NAT routing varies; the guest's source address may be translated. The --guest option must match the source IP the host actually sees. Prefer host-only networking for a distinct guest address; if NAT shares one source address between guests, the IP check cannot distinguish those guests. The random pairing credential remains required.

## Run on the host

Python 3.10+ is required. Windows needs no extra Python packages. Ubuntu hosts need `sudo bash setup-ubuntu.sh` once, followed by a full logout/login; run the receiver without sudo. The setup grants permission to create virtual input devices through /dev/uinput. macOS hosts need a virtual environment, `python3 -m venv .venv`, then `.venv/bin/python -m pip install -r requirements.txt`; grant Accessibility permission locally to Terminal/Python when instructed.

Example addresses below are placeholders: replace them with your host and guest addresses.

Windows host:

```powershell
py -3 host_receiver.py --bind 192.168.56.1 --guest 192.168.56.101
```

Ubuntu host:

```bash
python3 host_receiver.py --bind 192.168.56.1 --guest 192.168.56.101
```

Mac host:

```bash
.venv/bin/python host_receiver.py --bind 192.168.56.1 --guest 192.168.56.101
```

The receiver listens only on the specified host address, defaults to TCP port 8767, and rejects requests from other source IPs. Restrict any host firewall exception to the guest's address and that port. Do not disable your firewall or expose the port to the internet. Keep the host terminal open.

## Run inside the guest

Open the complete HTTP pairing address printed on the host in a desktop browser **inside the VM**. No Python is required in the guest. Alternatively run `python3 guest_controller.py` (or `py -3 guest_controller.py` on a Windows guest) and paste the URL when prompted. Do not open controller.html as a downloaded file.

Click Connect. Movement, left/right clicks, dragging, vertical scrolling, and speed adjustment operate the **host cursor**. Optional pointer capture uses Esc to exit. The VM application also has its own mouse-release shortcut; learn that shortcut before testing. Moving the host cursor can cause the VM window to lose focus or the guest pointer to leave the pad, depending on your VM integration settings; this version does not override that behavior. Disable optional seamless mouse integration in your VM application's settings if it interferes.

## Stop and limitations

Ctrl+C in the host receiver terminal stops control and invalidates the pairing credential. Disconnect stops browser input; held buttons release after about three seconds if connectivity is lost. Restarting the host receiver creates a new pairing code. Only one controller session is accepted at a time.

Host and guest must be trusted: HTTP is unencrypted. Possession of the pairing URL plus an allowed source address authorizes mouse control. It provides no screen sharing, keyboard access, elevated-desktop access, or lock-screen bypass. The host must be logged in to a graphical desktop, with normal OS input permissions enabled. macOS requires PyObjC; Ubuntu requires uinput access. See each platform's receiver documentation in the repository for details.

## Checks

`python3 -m unittest -v test_receiver.py test_guest.py` exercises the HTTP handler with a simulated mouse and checks the guest launcher's URL validation. No real mouse events are generated by these tests. Live host/guest networking, VM focus behavior, and host cursor movement still need verification with your VM application.
